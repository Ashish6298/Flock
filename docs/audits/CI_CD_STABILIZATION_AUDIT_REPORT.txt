7. STATIC TYPE ANALYSIS — ROOT CAUSE ANALYSIS & FIX
════════════════════════════════════════════════════════════════════

--- CI FAILURE ---
File     : src/flock/security/hardening.py
Line     : 37
Error    : Unused "type: ignore" comment  [unused-ignore]
Command  : mypy --strict src/
Exit code: 1

--- ROOT CAUSE ---
The original code read:

    else:
        is_admin = os.getuid() == 0  # type: ignore[attr-defined]

`os.getuid` does not exist in the Windows typeshed stub for the `os`
module. Therefore, on Windows, mypy correctly raises `attr-defined`
and the `# type: ignore[attr-defined]` comment is required to suppress
it.

On Linux (Ubuntu CI), `os.getuid` is present in the POSIX typeshed
stubs. Mypy resolves the attribute successfully and therefore considers
the `# type: ignore[attr-defined]` comment UNUSED, raising the strict
`[unused-ignore]` error that caused CI to fail.

This is a pure platform-divergence issue in mypy's typeshed stubs.
The code is guarded at runtime by `if sys.platform == 'win32':` /
`else:`, but mypy type-checks all branches using host-platform stubs,
not runtime control flow.

--- FIX APPLIED ---
Replace the direct attribute access with a `getattr`-based lookup.
`getattr` returns the callable (or None) without mypy ever trying to
resolve `os.getuid` as a direct attribute. No `# type: ignore` comment
is needed on any platform:

  BEFORE (line 37):
      is_admin = os.getuid() == 0  # type: ignore[attr-defined]

  AFTER (lines 36-37):
      _getuid = getattr(os, "getuid", None)
      is_admin = _getuid is not None and _getuid() == 0

This pattern:
  - Requires zero `# type: ignore` comments.
  - Passes mypy --strict on both Windows and Linux typeshed stubs.
  - Preserves correct runtime behaviour on all POSIX platforms.
  - Is functionally equivalent to the original implementation.

--- VERIFICATION AFTER FIX ---
